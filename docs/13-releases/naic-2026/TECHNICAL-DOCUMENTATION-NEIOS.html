1. What NEIOS is

NEIOS is governed developer infrastructure for N-ATLAS. It is the layer between a raw model endpoint and an organisational workflow: work is requested through structured intake, authorised by a deterministic policy gate before any model call, executed by N-ATLAS, validated against a strict schema, annotated with field-level provenance, routed to human approval when consequential, and recorded in an append-only audit trail. The model never decides its own authority.

Explicitly not: a prompt wrapper, a chat playground, a claim of official N-ATLAS/NITDA/Awarri affiliation, or a system where the LLM decides policy.

2. Architecture

Modular TypeScript monorepo (pnpm). One call path — all model access flows through a single provider interface; all output flows through the same governed loop.

ComponentRole
packages/natlas-adapterNAtlasProvider interface + OpenAI-compatible implementation. Endpoint, model and key fully configurable via env (NATLAS_BASE_URL, NATLAS_MODEL, NATLAS_API_KEY) — works against Ollama, vLLM or HF Inference Endpoints with zero code changes.
packages/governanceThe governed loop: APSOS intake packager, deterministic policy engine, invoice schema validation + deterministic arithmetic repair, field provenance annotator, approval routing, JSONL audit writer.
apps/vlthr-hr-webNext.js 15 control-first UI + API routes (/api/work, /api/approve, /api/audit). Shows the live 8-stage execution trace — not a chat box.
data/audit/audit-log.jsonlAppend-only audit trail; every run — successful, blocked, failed, approved, rejected — appends a record with input/output SHA-256 hashes.

3. The governed loop

REQUEST → CONTEXT → POLICY → MODEL → RESULT → EVIDENCE → APPROVAL → AUDIT
StageBehaviour
REQUESTHuman/system work request enters with a request ID.
CONTEXTAPSOS intake (WHO/WHAT/WHY/WHEN) packaged; missing material fields flagged before any model call.
POLICYDeterministic gate. Deny-by-default. BLOCK short-circuits the pipeline — the model is never invoked. REVIEW/ALLOW proceed.
MODELThe only place the provider is called. Latency and model identity recorded.
RESULTOutput parsed into a strict invoice_draft schema; arithmetic verified deterministically and repaired where verifiable — each correction is named in the trace and audit record. One bounded retry on malformed JSON.
EVIDENCEEvery field annotated input_fact / model_derived / system_derived — claims vs. verified inputs are distinguishable.
APPROVALLane-2+ (consequential) output remains a draft until a human approves or rejects; the decision itself is audited.
AUDITRecord appended for every run regardless of outcome — including policy blocks and model failures.

4. Model integration

  • Model: N-ATLaS 8B — hf.co/QuantFactory/N-ATLaS-GGUF:Q4_K_M (ungated community GGUF mirror of the official NCAIR1 weights).
  • Serving: Ollama on a rented RTX 3090 (vast.ai), OpenAI-compatible API at /v1/chat/completions.
  • Access: SSH tunnel only (127.0.0.1:18000). No public model port — Ollama ships without auth, so the auto-mapped port is explicitly not used.
  • Fallback path (documented): vLLM serving the gated NCAIR1/N-ATLaS weights with HF_TOKEN; the adapter is endpoint-agnostic.

6. Security & operations

  • Policy before model — the model cannot escalate its own authority (deterministic control, not prompt instruction).
  • Secrets in .env.local only — gitignored, never committed; history verified clean pre-push.
  • SSH-tunnelled model access; no public inference port.
  • Append-only audit with SHA-256 input/output hashes — tamper-evident.
  • Full deployment + restart runbook: engineering/runbooks/VASTAI-NATLAS.md. Running cost to date: $0.337 of a $5 credit (itemised in engineering/COST-LEDGER.md).
